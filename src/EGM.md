# src

## Overview

The whole Pi extension: it turns AWS Bedrock inference profiles into Pi models, signs the requests with the chosen AWS profile, keeps the prompt cache, renews an expired SSO sign-in, shows spend, and offers the `/bedrock` command family. `index.ts` (and the root `index.ts` that re-exports it) is a thin factory; `provider.ts` is the composition root that wires everything machine-wide (the commands, the footer, the selection guard, the SSO recovery). `preset-runtime.ts` holds one preset's state, and each preset is its own Pi provider, `jig-bedrock-<preset>`; the top level keeps the plain `jig-bedrock`. The words used here (AWS profile, inference profile, route, catalog) are defined in [How it works](../docs/how-it-works.md); every setting is in [Settings](../docs/settings.md).

This directory has no subdirectories. Its maintenance tooling is in [scripts](../scripts/EGM.md); the repository-level view is in the [root Blueprint](../EGM.md).

## Interface

**Entry.** `index.ts`: default export `jigBedrock()` (a Pi `ExtensionFactory`) and the named `jigBedrock(options?)`; type `BedrockOptions`. `options` replace the parts of the machine a test fakes: the catalog, the budget, the SSO recovery. `provider.ts`: `createBedrockProvider(options)(pi)`, `agentFolder`, types `BedrockOptions` and `BedrockHandle`.

## Invariants

- **The factory only registers.** At load it makes no network call, starts no process or timer, and writes no file; its promise is caught, so a failure never breaks Pi's start. AWS and the browser are touched only from `session_start` (in the background, not awaited) or from a command the user types. Nothing waits for AWS at start.
- **AWS profile names are read from the AWS config and credentials files, never from the AWS CLI.** Pi's own checks of the provider's credential start no program. `profile.ts` resolves the name in this order: the `profile` setting, `JIG_BEDROCK_PROFILE`, the AWS profile chosen at `/login`, `AWS_PROFILE`, `AWS_DEFAULT_PROFILE`, then the default profile if it exists. The result is cached for a minute.
- **Each preset is its own provider.** While `allPresetModels` is on (the default), every preset registers its models under `jig-bedrock-<preset>` and the top level keeps `jig-bedrock`, so `/model` lists them all at once; `isOwnModel` is true for the plain provider and for every preset's. The footer, the spend record and `/bedrock` follow the model in use, and each preset has its own budget and spend. With `allPresetModels: false` one plain provider carries the active preset's settings (0.6.3's shape).
- **One place decides the route.** `routeOf` in `catalog.ts` asks in order, and the first answer wins: not a Claude model, Converse; `api` is `converse` or the model is in `converseModels`, Converse; the model is in `messagesModels`, Messages; a known exception (today Opus 5), Converse; Pi lists the model and says mid-session tool changes work, Messages; otherwise Converse.
- **Requests carry only the AWS signature.** `createSignedFetch` removes the client's own `x-api-key` and `authorization` headers, signs only requests to `bedrock-runtime` hosts, and throws for any other host. Credentials come from the AWS SDK credential chain for the chosen AWS profile, loaded lazily, and are never written by this code.
- **An expired SSO sign-in is repaired once.** The expiry found while resolving credentials is returned as a synthetic 401 carrying `x-jig-sso-expiry`; `sso.ts` replays the request once, never a third time. `/bedrock login`, a failed request and sign-in at start share one recovery, so one browser opens however many need it. Any other credential failure is thrown as `CredentialFailureError` so its words reach the person.
- **No secret is asked for, stored or printed.** `/login` stores only the AWS profile name. `checkSso` answers with one word and reads the token cache for its expiry only. Diagnostics from `config.ts` name fields and never echo values. The debug log is off unless `JIG_BEDROCK_DEBUG=1` or `debug: true`, and then holds no prompt and no credential.
- **Writes are few and bounded.** Outside the cache, state and runtime folders the package writes three things: `bedrock.json` (the user's own settings; keys the package does not manage are left alone, and no secret reaches it), a one-time `.bedrock-first-run` marker (mode `0600`) beside it in Pi's agent folder, and the AWS CLI's shared config, which `aws-config-write.ts` only appends to: every existing byte kept, a temporary file, a lock file, the file's mode kept, a timestamped backup (the five newest kept). The AWS credentials file is never opened for writing.
- **Cache and state stay inside the `jig-bedrock` folder.** The roots may be links and are resolved, but from the `jig-bedrock` folder down a link is refused. The catalog is written by atomic rename. A changed setting discards the catalog.
- **Spend and refusals hold no identity.** A spend line has no prompt, ARN, account id or AWS profile name. The refusals record, kept seven days, has no account id. The monthly budget is a display figure, not an AWS limit.
- **Prompt cache by route.** The Messages route declares only the 5-minute lifetime, so `PI_CACHE_RETENTION=long` does nothing there; Converse keeps both lifetimes for Claude 4.5 and later. Older Claude and Nova take only 5 minutes; for Nova the lifetime is informative.
- **The region list is fixed, and a region not on it warns and is not refused**, so a new AWS region needs no release.
- **Output is plain.** Every `/bedrock` block is a title, marker rows, and at most one Next; with no UI it goes to standard output. Marks fall back to words under `TERM=dumb` or a non-UTF-8 locale. `doctor.ts` spawns with `shell: false`.
- **A setting changes in two places together.** Add the key to `FIELDS` in `config.ts` and its row to [Settings](../docs/settings.md); `test/docs.test.ts` checks both directions, and also that every `JIG_BEDROCK_` variable used here is named in that page.
- **A command changes in several places together.** Add an entry to `BEDROCK_COMMANDS`, a handler, and the pages that list commands; `test/docs.test.ts` checks the pages against the list.

## Side Effects

- **Network (signed HTTPS).** Requests go to `bedrock-runtime.<region>.amazonaws.com`. Discovery starts with an STS account check, then reads Bedrock inference profiles (or, in tag mode, the resource-tagging API); the package starts no `aws` program for it. Credentials come from the AWS SDK credential chain, which runs a program named by the profile's own `credential_process`. A call may take 20 seconds and a run stops at 90.
- **Child processes.** Five modules start a program. `aws-profile.ts` runs the AWS CLI (`aws sts get-caller-identity`). `login.ts` runs the sign-in command (default `aws sso login --profile {profile}`, or `ssoLoginCommand`), which opens a browser via `BROWSER` (the `browser` setting, or `bin/windows-browser` under WSL). `spend.ts` runs the user's `spendCommand`. `wsl.ts` probes Windows interop with `cmd /c exit`. `doctor.ts` runs local dependency checks.
- **Settings file.** Reads and writes `bedrock.json` in Pi's agent folder (`PI_CODING_AGENT_DIR`), from `/login`, `set`, `unset`, `budget`, `use`, `preset` and `migrate`. `migrate` writes with `wx` and mode `0600` and never overwrites. The same folder gets the one-time `.bedrock-first-run` marker the first time a session with a UI starts.
- **Runtime folder.** The sign-in lock `bedrock-sso.lock` (created with `wx`, mode `0600`) lives in `XDG_RUNTIME_DIR` when that is a safe absolute path, otherwise in `~/.local/state/jig-bedrock/sso-runtime`. A file here keeps two Pi processes from running the sign-in at once.
- **AWS shared files.** Reads the AWS config and credentials files (`AWS_CONFIG_FILE` and `AWS_SHARED_CREDENTIALS_FILE` honoured) for profile names, and the SSO token cache for its expiry time. Appends to the config only, as above.
- **Cache root** (`XDG_CACHE_HOME`, else `~/.cache`, under `jig-bedrock`): the catalog (`catalog.json`, and a hashed catalog file per setting set, old ones pruned to one per preset plus a spare, at most 32) and the refusals record.
- **State folder** (`XDG_STATE_HOME`, else `~/.local/state`, under `jig-bedrock`): monthly UTC spend lines in `spend/`, and the debug log `debug.log` (only when debug is on; at `MAX_LOG_BYTES` it rolls to `debug.log.1`).
- **Environment read:** `JIG_BEDROCK_TEAM`, `_PROFILE`, `_REGIONS`, `_DEBUG`, `_PRESET`, `_TAG_KEY`, `_TAG_VALUE`; `AWS_PROFILE`, `AWS_DEFAULT_PROFILE`, `AWS_CONFIG_FILE`, `AWS_SHARED_CREDENTIALS_FILE`, the AWS region and ambient-credential variables; `PI_CACHE_RETENTION`, `PI_CODING_AGENT_DIR`, `XDG_CACHE_HOME`, `XDG_STATE_HOME`, `XDG_RUNTIME_DIR`, `BROWSER`, `NO_COLOR`, `TERM`.
- **UI.** The footer, notices and `/bedrock` output go to Pi's UI. At session start discovery, the sign-in-at-start check and the spend command may begin in the background; `session_shutdown` aborts the session's lifetime signal and clears the footer.
